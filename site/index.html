Install job-hopper

job-hopper takes GitHub issues labelled hopper and runs each one as a Claude Code session on a machine you own. This page gets it running on one Linux host. On Windows it runs inside WSL, with the same install: start at On Windows. Full documentation: the README.

1. Before you start

On the host that will run the hopper:

NeedCheckWhy
Linux with systemd --usersystemctl --user statusthe daemon runs as a user service
git, Node.js ≥ 24, npmnode --versionthe install clones and builds the source
Docker, or a Postgres URLdocker compose versionthe hopper keeps everything in Postgres; with docker the install starts one
herdr at ~/.local/bin/herdrls ~/.local/bin/herdrjobs run in herdr panes
the claude CLI, signed inclaude --version, then run claude onceit runs the jobs and answers their questions
the gh CLIgh --versionreads and labels the issues that are jobs (step 4)

2. Install

curl -fsSL https://henningfutrell.github.io/hopper/install.sh | bash

It takes a few minutes. It does this, printing each step as ==> …:

  • checks for git, Node.js ≥ 24, npm and systemctl, and stops with a reason if one is missing;
  • clones the source into ~/.local/share/job-hopper/source;
  • starts a Postgres in docker on 127.0.0.1:5433 with a new password;
  • installs the daemon to ~/.local/lib/job-hopper and the job-hopper command to ~/.local/bin;
  • writes the settings file ~/.config/job-hopper/daemon.env (mode 600);
  • starts two user services: job-hopper and job-hopper-herdr.

Read the script before you run it: install.sh (the same file as scripts/get.sh).

Your own Postgres instead of docker

curl -fsSL https://henningfutrell.github.io/hopper/install.sh | JOB_HOPPER_DATABASE_URL=postgres://user:password@host:5432/hopper bash

Other settings

Set them in front of bash, the same way:

VariableDefaultWhat it sets
JOB_HOPPER_REFmainthe branch to install and to update from
JOB_HOPPER_REPOthis repositorywhere to clone from (your fork, for example)
JOB_HOPPER_SRC~/.local/share/job-hopper/sourcewhere the source clone lives
POSTGRES_PORT5433the loopback port of the docker Postgres

Check that it runs

systemctl --user status job-hopper job-hopper-herdr

Both must say active (running). If not, read the log:

journalctl --user -u job-hopper -n 50

To keep the services running after you log out: sudo loginctl enable-linger "$USER".

3. Open the UI

bash ~/.local/lib/job-hopper/scripts/open-ui.sh

This signs your browser in and opens http://127.0.0.1:4790/. No browser on this host? Run job-hopper login-code --link http://127.0.0.1:4790 and open the link it prints (it works once, for 10 minutes). Other ways to sign in: docs/sign-in.md.

4. Connect GitHub

On the same host, as the same user:

gh auth login
gh auth status

Pick GitHub.com, HTTPS, and log in with a web browser. gh auth status must say Logged in to github.com. The hopper picks it up on its own; no restart. To have a bot of your own act instead of your account, see A GitHub App of your own.

5. Give it its first job

  1. Say whose issues it takes, and in which repositories:

    job-hopper config edit plugins.yaml

    Under jobSources, on the github entry, set its options:

    authors: [your-github-login]
repos: [your-org/your-repo]
repoPaths: { your-org/your-repo: /path/to/a/checkout/of/your-repo }

    authors is required: issues by anyone else are not taken. A job runs in the checkout repoPaths names; without one, in your home directory.

  2. Restart the daemon so it reads the change:

    systemctl --user restart job-hopper

  3. Open an issue in that repository and add the label hopper. The issue text is the job's instructions.

  4. Watch it in the UI. The issue's labels show where it is: hopper:claimed while it runs, hopper:done and the issue closed when it finishes, hopper:failed if it fails (remove that label to run it again). Questions a job asks that need you wait in the UI's Questions view.

On Windows

The hopper runs inside WSL (the Linux that comes with Windows 10 and 11), from the same install command as on Linux. Do these steps first, then follow steps 1–5 above inside Ubuntu.

  1. Open PowerShell as administrator and install Ubuntu in WSL:

    wsl --install -d Ubuntu-24.04

    Restart Windows if it asks. Then open Ubuntu from the Start menu and choose a user name and password. Every command below runs in that Ubuntu window, not in PowerShell, unless it says so.

  2. Check that systemd runs:

    systemctl --user status

    If it says System has not been booted with systemd, turn systemd on:

    printf '[boot]\nsystemd=true\n' | sudo tee -a /etc/wsl.conf

    Then run wsl --shutdown in PowerShell, open Ubuntu again, and check again.

  3. Install git, Node.js 24 and Docker in Ubuntu. The service runs /usr/bin/node, so take Node.js from NodeSource, not from nvm:

    curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash -
sudo apt-get install -y git nodejs docker.io docker-compose-v2 gh
sudo usermod -aG docker "$USER"

    Close Ubuntu and open it again, so that you can use docker. Then install herdr and the claude CLI in Ubuntu as step 1 says, and sign in to claude.

  4. Install the hopper with the same command as on Linux:

    curl -fsSL https://henningfutrell.github.io/hopper/install.sh | bash

  5. Open the UI in your Windows browser. In Ubuntu, make a sign-in link:

    job-hopper login-code --link http://127.0.0.1:4790

    Open the link it prints in your Windows browser (it works once, for 10 minutes). WSL passes 127.0.0.1 through to Windows.

  6. Continue with step 4, Connect GitHub, in Ubuntu.

WSL stops Ubuntu, and the hopper with it, soon after you close the last Ubuntu window. Keep one Ubuntu window open while jobs run. Keep the repositories jobs work in inside Ubuntu (for example ~/src), not under /mnt/c: it is much faster.

Upgrade

Run the install command again. It updates the source and reinstalls; your settings and database stay. The UI also tells you when an update is available, and can apply it.

Uninstall

bash ~/.local/share/job-hopper/source/scripts/uninstall.sh

This removes the services and the installed code. It keeps the database, ~/.config/job-hopper and the source clone in ~/.local/share/job-hopper; delete those yourself if you want them gone.

If the install stops

It saysDo this
needs node on PATH (or git, npm, systemctl)Install it, open a new shell, run the command again.
needs Node.js >= 24Install Node.js 24 or later (for example with your package manager, or nvm).
needs systemd running for this userOn Windows, turn systemd on in WSL: On Windows, step 2. On Linux, log in to a normal session (not su or a bare container shell).
no databaseInstall docker, or give a Postgres URL as in Your own Postgres.
the docker volume job-hopper_postgres existsAn earlier install left its database. Give its URL with JOB_HOPPER_DATABASE_URL, or remove the volume with docker volume rm job-hopper_postgres (this deletes its data).
job-hopper: command not found (after the install)Add ~/.local/bin to your PATH, or run ~/.local/bin/job-hopper.
… has local changesSomeone edited the source clone. Commit or discard the changes there, or set JOB_HOPPER_SRC to another directory.
