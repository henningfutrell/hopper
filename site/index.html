Install job-hopper

job-hopper turns GitHub issues into finished work. You label an issue hopper; job-hopper starts a Claude Code session on your machine with the issue as its instructions, answers the questions it can, asks you the rest, and labels and closes the issue when the work is done.

This page takes you from nothing to a first finished job on one Linux machine. It takes about 15 minutes, most of it the install building itself. You need a terminal on that machine and a GitHub account.

Systems: Linux with systemd (Ubuntu, Debian, Fedora, Arch and most others). On Windows it runs inside WSL, with the same install: start at On Windows. Not yet macOS. With Docker, on any system: With Docker Compose.

1. Get what it needs

Do this on the machine that will run job-hopper, as the user it will run as (not root). First see what is there already:

for c in git /usr/bin/node npm curl systemctl gh claude docker ~/.local/bin/herdr; do command -v $c >/dev/null && echo found: $c || echo MISSING: $c; done; /usr/bin/node --version

Then install whatever it says is missing:

ProgramWhat it is forHow to get it
git, curlfetching the sourceyour package manager, for example sudo apt install git curl
Node.js 24 or later, with npm, at /usr/bin/noderuns job-hopperA system-wide install: the service runs /usr/bin/node, so a Node.js from nvm or fnm will not do. Your package manager if it has version 24, else the NodeSource packages (other ways: nodejs.org/en/download). /usr/bin/node --version must print v24 or higher
systemdkeeps job-hopper running in the backgroundalready there on most Linux systems. systemctl --user status must not print an error
Docker, with composeruns the database for youdocs.docker.com/engine/install, then let your user use it without sudo (post-install steps). Not needed if you have a Postgres database of your own (see below)
herdrthe terminal panes jobs run incurl -fsSL https://herdr.dev/install.sh | sh — installs to ~/.local/bin/herdr, where job-hopper looks for it. About herdr: herdr.dev
Claude Code (claude)does the work of each jobcurl -fsSL https://claude.ai/install.sh | bash, then run claude once and sign in. Details: Claude Code setup
GitHub CLI (gh)reads your issues and sets their labelscli.github.com. You sign it in at step 5

Run the check again until everything says found (docker may stay missing if you use your own Postgres).

2. Install

curl -fsSL https://henningfutrell.github.io/hopper/install.sh | bash

It prints each step as ==> … and takes a few minutes. It worked when the last lines show a health line and UI: http://127.0.0.1:4790/. If it stops with a message instead, find the message under When something goes wrong.

You can read the script first: install.sh (the same file as scripts/get.sh in the source).

What the install does
  • checks for git, Node.js 24 or later, npm and systemctl, and stops with a reason if one is missing;
  • downloads the source to ~/.local/share/job-hopper/source;
  • starts a Postgres database in docker on 127.0.0.1:5433, with a new random password;
  • installs job-hopper to ~/.local/lib/job-hopper and the job-hopper command to ~/.local/bin;
  • writes the settings file ~/.config/job-hopper/daemon.env, readable only by you (it holds the database password);
  • starts two background services for your user: job-hopper and job-hopper-herdr.

Nothing is installed system-wide and nothing runs as root. The web UI listens on this machine only (127.0.0.1:4790).

Use your own Postgres instead of docker

Give its address in front of bash. The database must exist and be empty or job-hopper's own:

curl -fsSL https://henningfutrell.github.io/hopper/install.sh | JOB_HOPPER_DATABASE_URL=postgres://user:password@host:5432/hopper bash
Other install settings

Set them in front of bash, the same way:

VariableDefaultWhat it sets
JOB_HOPPER_REFmainthe branch to install and to update from
JOB_HOPPER_REPOthis repositorywhere to download the source from (your fork, for example)
JOB_HOPPER_SRC~/.local/share/job-hopper/sourcewhere the source is kept
POSTGRES_PORT5433the port of the docker Postgres, on this machine only

3. Keep it running

Services for your user stop when you log out, unless you allow them to stay. Allow it once:

sudo loginctl enable-linger "$USER"

Then check both services:

systemctl --user status job-hopper job-hopper-herdr

Both must say active (running). Press q to leave. If one does not, see When something goes wrong.

4. Open the UI

On the machine itself, with a desktop and a browser:

bash ~/.local/lib/job-hopper/scripts/open-ui.sh

Your browser opens http://127.0.0.1:4790/, signed in.

From another computer (a server with no browser)

The UI listens on the server only, so reach it through ssh. On your own computer, connect with a tunnel and leave this terminal open:

ssh -L 4790:127.0.0.1:4790 you@your-server

In that ssh session, make a sign-in link:

job-hopper login-code --link http://127.0.0.1:4790

Open the link it prints in the browser on your own computer. It works once, for 10 minutes; make another the same way when you need one. Passwords, other people and other devices: docs/sign-in.md.

5. Connect GitHub

job-hopper uses the GitHub CLI, signed in as you, to read issues and set their labels. On the same machine, as the same user:

gh auth login

Answer GitHub.com, HTTPS, and Login with a web browser. On a server with no browser, it prints a one-time code and a web address: open the address on any device and enter the code. Then check:

gh auth status

It must say Logged in to github.com. job-hopper notices on its own; there is nothing to restart.

6. Give it its first job

A job runs Claude Code with every permission, without asking you, in the folder you give it. It can change files and run commands there as your user. Start with a test repository, and only let issues written by you become jobs.

  1. Pick a repository and a folder for its jobs. Use a repository on GitHub you can write to, and a clone of it on this machine — for example:

    git clone https://github.com/your-login/your-repo ~/your-repo

  2. Tell job-hopper whose issues to take, and from where. Open its settings in your terminal editor:

    job-hopper config edit plugins.yaml

    Under jobSources:, find the entry with name: github and replace it with this, using your GitHub login, your repository and the folder from step 1:

      - name: github
    plugin: github-gh
    options:
      enabled: auto
      authors: [your-login]
      repos: [your-login/your-repo]
      repoPaths: { your-login/your-repo: ~/your-repo }

    Save and close the editor. authors is required: issues opened by anyone else are never taken. repos limits which repositories it looks at; without it, it looks at every repository you own. A job from a repository not in repoPaths runs in your home folder. The editor is $EDITOR, or vi if that is not set: run EDITOR=nano job-hopper config edit plugins.yaml for a simpler one.

  3. Restart job-hopper so it reads the change:

    systemctl --user restart job-hopper

  4. Create the hopper label in the repository, once:

    gh label create hopper -R your-login/your-repo

  5. Open an issue with the label hopper. The issue text is the job's instructions. A small first job works best, for example "Add a line to README.md saying this repository is a test."

  6. Watch it. job-hopper checks GitHub every minute, so the job starts within a minute. The issue's labels show where it is:

    LabelMeans
    hopper:claimedit is running; the UI's board shows it
    hopper:doneit finished, and the issue is closed
    hopper:failedit failed; remove this label to run it again

    When a job asks something it cannot answer for itself, the question waits for you in the UI's Questions view.

That is the whole loop. From here, label any issue hopper to hand it over. hopper:high and hopper:low change its priority; hopper:backburner keeps it waiting.

With Docker Compose

Instead of steps 1 to 5: job-hopper, its database and the panes its jobs run in, all in containers. Nothing is installed on the machine itself, and it works wherever Docker runs. You need only Docker, with compose.

  1. Get the compose file and start it, in a folder of its own. The first start builds job-hopper, which takes a few minutes:

    mkdir job-hopper && cd job-hopper
    curl -fsSLO https://henningfutrell.github.io/hopper/compose.yaml
    docker compose up -d --build

    Run the later commands in this folder too.

  2. Open the UI. Make a sign-in link and open it in your browser:

    docker compose exec hopper job-hopper login-code --link http://127.0.0.1:4790

  3. Sign in to GitHub and to Claude Code, inside job-hopper's container. Once is enough: both are kept when it restarts or upgrades.

    docker compose exec -it hopper gh auth login
    docker compose exec -it hopper claude

    In Claude Code, type /login, follow it, then /exit. Then say who jobs commit as:

    docker compose exec hopper git config --global user.name "Your Name"
    docker compose exec hopper git config --global user.email you@example.com

  4. Give it its first job as in step 6, with these commands in place of its first three:

    docker compose exec hopper git clone https://github.com/your-login/your-repo /home/node/your-repo
    docker compose exec -it hopper job-hopper config edit plugins.yaml
    docker compose restart hopper

Upgrade: docker compose up -d --build. Stop: docker compose down (everything is kept); docker compose down -v also deletes its database and sign-ins. Settings, a reverse proxy and secrets: docs/deploy.md.

On Windows

job-hopper runs inside WSL (the Linux that comes with Windows 10 and 11), with the same install command as on Linux. Do these steps first; then continue with step 5, Connect GitHub, in Ubuntu.

  1. Open PowerShell as administrator and install Ubuntu in WSL:

    wsl --install -d Ubuntu-24.04

    Restart Windows if it asks. Then open Ubuntu from the Start menu and choose a user name and password. Every command below runs in that Ubuntu window, not in PowerShell, unless it says so.

  2. Check that systemd runs:

    systemctl --user status

    If it says System has not been booted with systemd, turn systemd on:

    printf '[boot]\nsystemd=true\n' | sudo tee -a /etc/wsl.conf

    Then run wsl --shutdown in PowerShell, open Ubuntu again, and check again.

  3. Install git, Node.js 24, Docker and the GitHub CLI in Ubuntu. Node.js comes from NodeSource, so it is at /usr/bin/node:

    curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash -
sudo apt-get install -y git nodejs docker.io docker-compose-v2 gh
sudo usermod -aG docker "$USER"

    Close Ubuntu and open it again, so that you can use docker. Then install herdr and Claude Code as step 1 says, sign in to claude, and run the check from step 1.

  4. Install job-hopper with the same command as on Linux:

    curl -fsSL https://henningfutrell.github.io/hopper/install.sh | bash

  5. Open the UI in your Windows browser. In Ubuntu, make a sign-in link:

    job-hopper login-code --link http://127.0.0.1:4790

    Open the link it prints in your Windows browser (it works once, for 10 minutes). WSL passes 127.0.0.1 through to Windows.

  6. Continue with step 5, Connect GitHub, in Ubuntu, and then step 6.

WSL stops Ubuntu, and job-hopper with it, soon after you close the last Ubuntu window; step 3 does not change that. Keep one Ubuntu window open while jobs run. Keep the repositories jobs work in inside Ubuntu (for example ~/src), not under /mnt/c: it is much faster.

Upgrade

Run the install command again. It updates job-hopper and keeps your settings, database and running jobs. The UI also tells you when an update is out, says what is new, and can apply it for you.

Uninstall

bash ~/.local/share/job-hopper/source/scripts/uninstall.sh

This stops the services, closes running jobs, and removes the installed program. It keeps your data: the database, ~/.config/job-hopper and the source in ~/.local/share/job-hopper. Delete those yourself if you want them gone. The docker database also stays; to delete it and its data: docker rm -f job-hopper-postgres-1 && docker volume rm job-hopper_postgres.

When something goes wrong

The install stops

It saysDo this
needs node on PATH (or git, npm, systemctl)Install it (step 1), open a new terminal, run the install again.
needs Node.js >= 24Your Node.js is too old. Install a newer one from nodejs.org, open a new terminal, check node --version.
needs systemd running for this userOn Windows, turn systemd on in WSL: On Windows, step 2. On Linux, log in to a normal session (not su or a bare container shell).
no databaseInstall docker, or give a Postgres address as in Use your own Postgres.
permission denied … docker.sockYour user may not use docker yet. Follow docker's post-install steps, log out and back in, run the install again.
the docker volume job-hopper_postgres existsAn earlier install left its database. Give its address with JOB_HOPPER_DATABASE_URL, or delete it with docker volume rm job-hopper_postgres (this deletes its data) and run the install again.
… has local changesSomeone edited the downloaded source. Undo the changes there, or set JOB_HOPPER_SRC to another folder.
did not answer /api/healthjob-hopper did not start. Read why with journalctl --user -u job-hopper -n 50.

After the install

What you seeDo this
job-hopper: command not foundAdd ~/.local/bin to your PATH (open a new terminal; many systems add it when it exists), or run ~/.local/bin/job-hopper.
job-hopper-herdr is failedherdr is missing from ~/.local/bin/herdr. Install it (step 1), then systemctl --user restart job-hopper-herdr.
job-hopper is not runningRead why: journalctl --user -u job-hopper -n 50. If it says /usr/bin/node is missing or too old, install Node.js system-wide (step 1), then systemctl --user restart job-hopper.
The services are gone after you log outDo step 3, then systemctl --user start job-hopper-herdr job-hopper.
The UI does not open, or asks you to sign inMake a new sign-in link: job-hopper login-code --link http://127.0.0.1:4790. From another computer, use the ssh tunnel.
A labelled issue is not picked up after a few minutesCheck: you opened it, and your login is in authors; its repository is in repos; the label is exactly hopper; gh auth status says logged in; you restarted job-hopper after editing. The UI's Sources view shows whether the GitHub source is running or paused.
A job is hopper:failed at onceIts folder in repoPaths may not exist, or claude is not signed in: run claude once. The job in the UI says why it failed.
