# Proposal

Use this skill when the job is asked for a proposal, not to do the work.

## Method

1. State the problem in a few sentences. Say what a good result is.
2. Read the code and the rules that limit the answer: the repository's rules, its design documents, and the issues that
   decided something before.
3. Find more than one path when more than one is real. A path that you would never recommend is not a path.
4. For each path, say what it changes, its security effect, its effort, its risk, the friction for a person, and the
   jobs or issues it creates.
5. Recommend one path, or a combination that goes together, and say why in one or two sentences.

## The proposal

Write it as the job rules say, with its labels in order. When no change is needed or no path is viable, say so, and say
why. Do not change code while you write a proposal.
